# 文献精读助手 v0.1.0 设计规格

## 1. 项目目标

创建一个面向学术研究者的通用 Codex Skill，以单篇学术文献为处理单位，接收本地 PDF 或 Zotero 文献条目，按照“定位、解构、取证、重构、审辨、迁移、凝练”七阶段流程生成可长期维护的 Markdown 精读产物。

产物优先适配 Obsidian。所有可供后续引证的重要判断必须回溯到页码级原始证据。Skill 辅助研究者理解和组织文献，不替代原文阅读、引文核对与最终学术判断。

## 2. 名称与版本

- 中文显示名：文献精读助手
- 英文显示名：Literature Deep Reading Assistant
- Skill 名称：`literature-deep-reading-assistant`
- GitHub 仓库：`https://github.com/chaogao512/Literature-Deep-Reading-Assistant`
- 首个版本：`0.1.0`
- 许可证：MIT，以仓库现有 `LICENSE` 为准
- 版本规则：采用语义化版本；`VERSION`、`CHANGELOG.md`、Git 标签和 GitHub Release 保持一致

## 3. 首版范围

v0.1.0 一次只精读一篇文献：

- 一个本地 PDF；或
- 一个 Zotero 文献条目及其 PDF 附件。

不包含批量精读、跨文献综合、自动写入 Zotero、自动安装 OCR 工具、自动形成可直接提交的论文段落。

## 4. 自动触发条件

触发条件必须同时写入 `SKILL.md` 的 YAML `description` 和正文边界说明。

### 4.1 应自动触发

当用户提供或指向单篇学术文献，并要求完成下列任一任务时自动触发：

- 精读、深读、系统阅读或批判性阅读文献；
- 分析论文的研究问题、理论、方法、证据、机制、结论或边界；
- 生成文献阅读笔记、精读卡、证据卡或 Obsidian 文献笔记；
- 从本地 PDF 或 Zotero 文献生成可追溯的精读产物；
- 使用七阶段流程对单篇文献进行结构化分析；
- 提取能够回链到页码和原文证据的观点或命题。

### 4.2 不应自动触发

以下任务不自动触发：

- 仅查找、推荐、下载或罗列文献；
- 仅转换 PDF、执行 OCR、翻译全文或修改 PDF；
- 仅生成一种参考文献格式；
- 多篇文献的系统综述、元分析或横向综合；
- 未提供可访问原文时，仅根据题名或摘要猜测全文；
- 普通网页、教材章节或非学术文档的一般摘要，除非用户明确要求按本 Skill 精读。

### 4.3 显式调用示例

- “使用 `$literature-deep-reading-assistant` 精读这篇 PDF。”
- “从 Zotero 读取这篇文献，按七阶段生成 Obsidian 笔记。”

## 5. 总体架构

采用混合编排架构：

- `SKILL.md`：输入识别、工具路由、七阶段主流程、停止条件和验收规则；
- `references/`：文献类型路由、证据契约、Obsidian 规范、引文规范和七阶段细则；
- `scripts/`：PDF 可读性诊断、安全目录命名、产物初始化和证据链接审计；
- `assets/note-templates/`：运行时使用的 Markdown 模板；
- 模型：负责文献分类、论证还原、证据解释、知识重构和学术审辨；
- 脚本：只处理可确定、可重复验证的机械操作。

## 6. 文档读取与依赖降级

### 6.1 本地 PDF

1. 诊断文件有效性、页数、文本层和页面文本覆盖情况。
2. PDF 可直接阅读时，使用可用的 PDF 读取能力提取全文，并在图表、页码或版面关系重要时渲染相关页面核验。
3. PDF 有文本层但直接读取质量较差时，仅在环境中已经存在兼容的文档转换 Skill 时调用它。
4. PDF 为扫描件时，仅在环境中已经存在兼容的 OCR Skill，例如 `academic-pdf-to-md` 或 MinerU 时调用。
5. 不自动安装缺失的转换或 OCR Skill。
6. 扫描件不可读且无 OCR 能力时停止，明确告诉用户该文档当前不可读，请用户自行决定是否采用 OCR 工具。
7. 不根据题名、摘要、目录或残缺文本推断全文内容。

### 6.2 Zotero

1. 使用 Zotero 的只读能力检索文献。
2. 多条结果匹配时要求用户确认具体条目。
3. 读取题录、item key、citation key、附件 key、附件路径或索引全文。
4. 优先读取 PDF 附件；只有索引全文而无 PDF 时，允许分析文本，但凡涉及精确页码的证据均标注“页码待核实”。
5. 不修改 Zotero 条目，不移动或复制受管附件。

## 7. 七阶段工作流

### 7.1 定位

识别研究对象、核心问题、文献类型、研究层次、作者意图和精读价值，生成阅读策略卡。先分类，再决定后续模块和精读深度。

### 7.2 解构

脱离论文目录，还原“问题、概念或理论、分析或证据、发现或模型、结论”的论证链，生成文章骨架和关键跳步。

### 7.3 取证

从问题、概念、理论、分类、模型、机制、方法、证据、结果和边界模块中动态选择相关模块。每项关键证据必须形成可寻址的原始证据记录。

### 7.4 重构

区分原文层、分析层和研究层，生成概念卡、命题卡、关系卡和框架卡。卡片按需创建，不强制凑齐类别。

### 7.5 审辨

在忠实还原完成后，分别审查概念、分类、逻辑、方法、证据与外推边界。严格区分“作者提出了什么”和“作者证明了什么”。

### 7.6 迁移

用户提供研究语境时，使用 `CITE`、`CONCEPT`、`FRAMEWORK`、`METHOD`、`EVIDENCE`、`GAP`、`REFERENCE` 和 `CHALLENGE` 标签分析可迁移价值。用户未提供研究语境时，只给出一般学术价值，并标注“待结合具体研究问题判断”。

### 7.7 凝练

分别形成作者结论、核心学术命题、知识增量、可信边界和个人研究价值。不得把摘要改写当作最终精读结论。

## 8. 原始证据契约

`03-取证.md` 中每项可供引证的证据使用稳定编号和 Obsidian 块标识：

```markdown
### E01 证据标题

- 原文短摘录或忠实转述：……
- 证据类型：作者定义／理论推演／文献证据／政策依据／定量结果／定性材料／案例材料／作者主张
- 页码：PDF 第 8 页；正文标注第 126 页
- 对应命题：P01 ……

^e01
```

强制规则：

- 四个字段不可缺失；无法确认时写“待核实”，不得留空或编造；
- 短摘录必须保持原义，忠实转述不得伪装成直接引语；
- 同时记录 PDF 文件页序和正文标注页码；无法识别其中一项时明确说明；
- 后续文件使用 `[[03-取证#^e01]]` 回链，不只链接文件或普通标题；
- 每个回链必须指向真实存在且唯一的块标识；
- 审辨、迁移和凝练中的关键判断若无证据支撑，标注为“分析性判断”或“待核实”，不得伪装成作者结论。

## 9. 稳定标识与目录命名

- 优先使用 Zotero citation key 作为 `paper_id`；没有时使用“第一作者-年份-短题名”的稳定组合；
- 目录名只使用安全化后的短题名，不把目录名当作唯一标识；
- 移除或替换 `/ \\ : * ? \" < > |`、控制字符、末尾空格和句点；
- 处理 Windows 保留名和空题名；
- 同名目录存在时追加稳定短哈希，不覆盖旧产物；
- 完整原题名保存在 `00-文献索引.md`。

## 10. 输出位置

- 用户提供 Obsidian Vault 或目标目录时，写入指定位置；
- 本地 PDF 未指定目录时，在 PDF 所在目录创建短题名目录；
- Zotero 文献未指定目录时先询问用户，不写入 Zotero 受管附件目录；
- 不持久保存用户私人路径；
- 默认不复制、移动或重命名原始 PDF。

## 11. Obsidian 产物结构

```text
安全化短题名/
├── 00-文献索引.md
├── 01-定位.md
├── 02-解构.md
├── 03-取证.md
├── 04-重构.md
├── 05-审辨.md
├── 06-迁移.md
├── 07-凝练.md
└── cards/
    ├── 概念卡-*.md
    ├── 命题卡-*.md
    ├── 关系卡-*.md
    └── 框架卡-*.md
```

所有阶段文件使用 YAML 属性记录 `paper_id`、完整题名、阶段、来源类型、处理状态和生成日期。`00-文献索引.md` 汇总引用信息、来源链接、阅读状态、阶段文件双链和卡片索引。

## 12. 原始 PDF 与来源链接

- Zotero 来源记录 item key、citation key 和附件 key，并生成可用的 `zotero://select/`、`zotero://open-pdf/` 及页码跳转链接；
- 本地 PDF 记录绝对来源路径、文件名、文件大小和 SHA-256；
- PDF 位于 Obsidian Vault 内时可增加相对双链；
- 不复制 PDF 是默认行为。

## 13. 引用格式

- 默认输出 GB/T 7714—2025；用户可指定其他格式；
- Zotero 来源优先使用已核实的 Zotero 元数据和可用的引用格式化能力；
- 本地 PDF 只使用正文、题录页、DOI 信息或用户提供的可靠元数据；
- 缺失字段明确列出，不臆造作者、年份、卷期、页码、DOI 或文献类型；
- 无法确认格式细节时，将引用标记为“待按原文或文献管理器核对”。

## 15. 图标与 README

- 使用 gpt-image-2 生成一个方形、无文字的品牌图标；
- 形象突出教育技术博士、学术文献、证据追踪和数字化阅读；
- 避免复杂场景、照片式人物、学校标志和难以缩放的细节；
- 最终图标保存到 `assets/readme/`，并生成 Skill UI 所需尺寸副本到 Skill 的 `assets/`；
- README.md 为英文，README.zh-CN.md 为简体中文；
- 两份 README 均说明用途、触发方式、安装、输入、产物目录、证据回链、依赖降级、使用示例、局限和许可证；
- 使用 `humanizer-zh` 对中英文内容进行自然化审校，避免宣传腔和模板化表达。

## 16. ccswitch 打包

发布文件：`dist/literature-deep-reading-assistant-v0.1.0-ccswitch.zip`。

ZIP 根目录必须直接包含：

```text
SKILL.md
agents/
references/
scripts/
assets/
```

ZIP 不包含仓库 README、根目录展示资源、设计文档、示例、测试、打包工具、`.git`、缓存、临时文件或 `__pycache__`。生成 `dist/SHA256SUMS`，并验证 ZIP 完整性与文件清单。

## 17. `.gitignore`

忽略操作系统文件、编辑器配置、Python 缓存、测试缓存、虚拟环境、环境变量、日志、本地临时文件和测试输出。保留 `assets/readme/`、`examples/`、`dist/*.zip`、`dist/SHA256SUMS`、README、版本记录和设计文档。

## 18. 验收标准

1. Skill Creator 结构校验通过。
2. 四个脚本分别通过正常、边界和失败输入测试。
3. 安全目录命名覆盖非法字符、保留名、空题名和同名冲突。
4. 产物初始化生成完整的八个阶段文件和 `cards/`。
5. 证据审计能发现缺字段、重复块标识、悬空回链和未回链的重要命题。
6. 扫描件且无 OCR 能力时正确停止，不猜测内容。
7. ccswitch ZIP 的 `SKILL.md` 位于根目录，内容清单合规，无缓存。
8. 中英文 README 链接有效，图标在 GitHub 和 Skill UI 中可用。
9. `VERSION`、CHANGELOG、ZIP 文件名、Git 标签和 Release 版本一致。
10. 本地 `main` 与远程 `origin/main` 同步。

## 19. 安全与学术边界

- 不发明事实、引文、页码、统计结果或参考文献信息；
- 不把模型推断标记为作者原意；
- 不覆盖用户已有精读目录；
- 不擅自安装依赖、修改 Zotero 或移动原始文献；
- 不声称“精读完成”，除非全文可读、七阶段产物齐全且证据回链审计通过；
- 最终学术判断、引用核对和论文写作责任属于使用者。
